# v0.3.0 — approved application workflows

This release adds durable extension workflows, frozen environment scopes,
independent approvals, deterministic child commands and locally verified Agent
scope checks. The shared UI supports composed navigation and embedded management
publications. Existing publication and image preparation APIs remain available.

Schema **v5** requires an explicit initial migration. Back up the management
store and Agent journals, stop the API, run the matching `admin-api -migrate`,
and start the matching API/Web/Agent. Normal image updates never run migrations.
See [workflow contract and recovery](workflows.md).

Validation includes full unit and race suites, real MySQL v4→v5 migration,
standalone archive builds, desktop/mobile composition checks, immutable image
preparation, management API/Web single and paired updates, restart recovery and
health-failure rollback. Source, Git history, source archives and executable
artifacts are scanned before publication. Remote CI and signed image manifests
are recorded separately with their exact run and commit identities.

OCI SHA tags include architecture so separate amd64/arm64 workflow runs do not
overwrite each other. Deployment identities remain signed immutable digests;
timestamps and readable tags are display metadata.
