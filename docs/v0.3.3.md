# v0.3.3 — Signed build registration compatibility

GitHub build registration now uses the shared manifest validator when matching
provenance. This accepts both historical v1 manifests and current v2 manifests
with signed build timestamps. Previously the provenance matcher rejected all
v2 artifacts, despite successful signature verification.

Repository, workflow, branch, commit, run and attempt must still match the
independently retrieved GitHub run. Unsupported schemas and invalid timestamps
remain rejected. No database migration or approval-policy change is required.
