# v0.3.2 — Docker image-store identity compatibility

Cache preparation workflows may bind both the signed image configuration ID
and the exact approved manifest digest. Modern Docker image stores can return
the latter as the local image ID. No tags or arbitrary IDs are accepted, and
both the immutable reference and platform must still match the receipt.

Service mutations continue to freeze a single actual runtime image identity.
Providers should resolve that identity from the verified preparation receipt;
existing Docker locators remain unchanged for execution and rollback.

Schema remains v5. This fixes preparation rejection exposed by pulling an
actual signed CI image on a current Docker engine. API/Web/Agent are published
as a matching release; no automatic database migration is introduced.
